# Contract: Chat API

**Date**: 2026-11-21
**Consumer**: The React frontend, in the browser.
**Provider**: The Spring Boot backend.

## POST /api/chat

Send one user message in a session and receive the assistant reply as a stream.

### Request

- **Headers**: `Content-Type: application/json`
- **Body**:

```json
{
  "sessionId": "b7f1c2e0-5d8a-4c1e-9a3b-2f6e1d0c9a71",
  "message": "Why am I getting 429 errors on the free tier?"
}
```

| Field | Type | Required | Rules |
|-------|------|----------|-------|
| `sessionId` | string | yes | Non-blank. Generated by the client. |
| `message` | string | yes | Non-blank. At most 2,000 characters. |

### Response: success

- **Status**: `200 OK`
- **Content-Type**: `text/event-stream`

Events, in order:

| Event | Data | Meaning |
|-------|------|---------|
| `token` | `{"text": "<fragment>"}` | A piece of the reply. Zero or more. |
| `done` | `{}` | The reply finished normally. Exactly one, last. |
| `error` | `{"message": "<friendly text>"}` | The reply failed. Terminal. Replaces `done`. |

Example stream:

```text
event: token
data: {"text": "Free-tier requests are "}

event: token
data: {"text": "limited per minute. "}

event: done
data: {}
```

The `error` event `message` is always user-safe text. It MUST NOT contain stack traces, provider
error payloads, or API keys (constitution II and IV).

### Response: rejected before streaming

Returned as JSON, not as a stream.

| Status | When | Body |
|--------|------|------|
| `400 Bad Request` | `sessionId` or `message` missing or blank | `{"error": "Please enter a message."}` |
| `413 Payload Too Large` | `message` longer than 2,000 characters | `{"error": "Messages must be 2,000 characters or fewer."}` |
| `429 Too Many Requests` | Per-session rate limit exceeded | `{"error": "You're sending messages too quickly. Please wait a moment."}` |
| `403 Forbidden` | Request origin is not the frontend origin | `{"error": "Request not allowed."}` |

Each rejected response body contains only the `error` key with user-safe text.

## Cross-origin rules

- Only the configured frontend origin is allowed (spec FR-014, constitution IV).
- The origin is configured in `application.yml`, not hardcoded.

## Conformance checks

1. A valid request returns `text/event-stream` and ends with exactly one `done` or `error` event.
2. A blank message returns `400` with the JSON error body, not a stream.
3. A 2,001-character message returns `413`.
4. A simulated provider failure returns an `error` event with no stack trace text.
5. Logs for a request contain session ID, latency, and outcome, and do not contain `message` text.
